# ADR-004 改核心之前先在整套副本上試，測試期間正式環境寫入 0

**背景**：原系統的角色有長期累積的記憶。技術測試直接打在正式環境過一次：測試訊息被當成真的對話寫進記憶、更新了情緒狀態。弄髒一次，就再也分不清哪些是真的。

**決定**：整套系統複製一份副本來測。測試行程由守門程式包住：寫正式路徑、連正式服務、從正式路徑啟動行程，一律擋下並計數。建好副本先放金絲雀——故意做幾個該被擋的動作——全部抓到才開始用。每批修改上線前，守門紀錄要能說出「擋下幾次、放行的正式寫入 0 次」。

**代價**：副本要跟正式環境一樣大，要定期重建；跟正式環境共用的服務（向量、模型）測試時會搶資源、會在正式帳本留紀錄，要明寫才放行。守門只攔它看得到的門，沒攔到的要照實列。

**反例**：`tests/test_verification.py::test_counterexample_without_the_guard_the_test_writes_into_production`——沒有守門，同一段測試把檔案寫進正式資料夾，沒人擋、沒人數。
