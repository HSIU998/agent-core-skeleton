# ADR-003 驗收分兩層：程式有在跑，跟目標有沒有達到

**背景**：一批修改全部通過檢查，但問「每一項的最終目標達到了沒」時答不出來。檢查只證明程式照寫的跑。

**決定**：每一項修改動手前先寫三欄——最終目標（使用者感受得到的一句話）、量什麼、過關線。驗收時分開記；只有程式層通過的，不算修好。後來再細分成五類：確定好了、觀察期、部分好了、沒過、還沒碰。

**代價**：每一項都要多寫一把尺，而且有些目標很難量（例如「口氣像不像本人」）。量不出來的，就老實標「觀察期」，不升級成「好了」。

**反例**：本倉庫每個模組的測試都附一個「拿掉這個做法會怎樣」的反例，證明測試量的是行為，不是程式有沒有被呼叫。
